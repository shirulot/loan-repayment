# 提前还贷计算器

一款用 Flutter 编写的离线房贷规划工具。输入商贷、公积金贷款和每月现金流，就能逐月查看月供、本金、利息和预计结清月份。已有银行账单时，可以从实际余额接着推算，比较一次提前还款前后月供降了多少。

项目包含 Android、iOS、macOS 和 Windows 客户端。贷款数据保存在本机，无需注册账号。联网功能用于更新中国节假日和调休安排。

## 快速开始

准备包含 Dart `^3.12.2` 的 Flutter SDK 和目标平台的开发工具后，在终端执行以下命令。

```bash
git clone https://github.com/shirulot/loan-repayment.git
cd loan-repayment
flutter pub get
flutter devices
flutter run
```

连接多个设备时，用 `flutter run -d <设备ID>` 指定目标。在 macOS 上可直接运行 `flutter run -d macos`，在 Windows 上使用 `flutter run -d windows`。

**第一次做计划**，在「首页 → 本金与利率 → 测算基准本金」填写当前用于测算的商贷和公积金本金，再填写年利率、贷款期限，选择等额本金或等额本息，点「应用并重算」。如果手里已有历史账单，也可以先从「还款计划 → 导入或导出 → 导入历史还款 JSON」录入，从最后一张账单的期末余额继续规划。

## 功能导览

| 页面 | 可以做什么 |
| --- | --- |
| 首页 | 编辑本金、利率和现金流，录入或修正提前还款，查看最近一笔还款和未来三期预览。顶部的眼睛按钮可隐藏金额，齿轮按钮可选择跟随系统、白天或黑夜模式。 |
| 还款计划 | 查看每月本息、剩余本金及同月每笔提前还款，选择表格列，比对两行，导入账单或导出计划。宽窗口可并排编辑参数和查看表格。 |
| 计算器 | 输入带括号的四则运算，搜索并引用首页或计划中的数值，暂存结果。空算式插入暂存值可恢复原算式，已有算式则插入一个引用。 |
| 日历 | 左滑日期网格到下月、右滑到上月，点日期查看当天明细。支持公历、农历、节假日、调休、扣款和备注。宽屏并排显示月历和明细。 |

### 安排提前还款

「首页 → 还款频率」提供三种提前还款方式。

| 方式 | 未录入单笔交易的月份如何安排 |
| --- | --- |
| 增量还款 | 按周期累计各月可用于还款的正结余，到期时将自动金额向上取整到十元。 |
| 定额还款 | 每个周期使用一次手填金额。例如每三个月还 5 万元，到期使用 5 万元。 |
| 手动还款 | 只计算正常月供，另有提前还款时在「最近三笔还款」录入金额和日期。 |

增量和定额的周期可选 1–12 个月，以当前计算月份为起点。已录入的交易优先，归还本金以剩余贷款为限。同一个月可以有多笔，首页显示最近三笔，其他记录仍参与完整计划。录入的有效金额和日期会自动同步。贷款参数和还款频率通过「应用并重算」生效。

已标为「已结清」的提前还款可点「修正」调整金额或日期，再点「确认」。首页的「最近一笔还款」按计划中截至今天的交易日期查找。

首页「未来3期还款预览」按周期汇总提前本金，并显示期末剩余本金。点一次选中，再点选中的月份进入详情，可左右滑动查看相邻月份。「查看详情」打开完整计划表。

### 核对月供和逐笔差额

- **公历月份固定显示**，在「列设置」开启农历月份后，两个月份列会一起冻结。可分别查看两类贷款的月供本金、利息、减少额和余额。有提前还款的月份按交易逐行显示，首笔行承载当期正常月供，后续行展示各笔还款前的月供和还款后的余额。
- 点**「比差」**后，依次选两条实际显示的行，可以跨月，也可以选同月的两笔交易。结果页包含隐藏列。金额按「第二行 − 第一行」计算，先各自取到分。公历月份按月比较，扣款日期按天比较。
- 如果月供从 3,000 元降到 2,900 元，计划表的「减少额」是 100 元。按先后顺序选这两行，「比差」里的月供差额是 −100 元。首页、计划和比差页共享金额脱敏开关，导出文件使用实际数值。

### 日历和通知

在「扣款日」中分别设置商贷、公积金规则，用加号添加单次或每月重复备注。月度规则支持固定日期、指定日期后的首个或第几个工作日，以及当月第几个工作日。录入的提前还款也会关联到对应日期。

两类贷款按各自的**还款账期**判断是否结清。例如，商贷已还清、公积金仍有月供，同一天只显示公积金扣款。最后一期有金额的月供会保留，即使扣款日因工作日规则顺延到次月。结清后的零元扣款不再生成日历标记、未读角标或系统通知。原扣款规则仍可在设置中查看。历史账单优先使用银行实扣日期，缺少日期时按对应规则定位，归档事项不触发提醒。

Android、iOS 和 macOS 接入了本地通知，启用提醒时可按系统提示授权，点击通知可打开相应日期。Windows 可使用应用内日历。调休数据在打开应用或回到前台时按自然月检查，尝试获取当年和次年的数据。离线时继续使用已缓存和内置的日历。

## 计算规则

| 项目 | 应用采用的口径 |
| --- | --- |
| 起算本金 | 「初期贷款信息」记录原始本金和日期。「测算基准本金」用于预测。已有历史账单时采用最近账单的期末本金并只读展示。无历史账单时，计划首行校准余额，正常月供从下一行开始。 |
| 期限与还款方式 | 可根据贷款开始月份和总年数推算剩余期数，也可反向调整。商贷和公积金共用等额本金或等额本息的选择，分别计算后合计。 |
| 商贷利息 | 等额本金的增量和定额模式按上个自然月实际天数、年利率及 360 天基数计息。手动模式在上月有提前还款时使用该口径，其他月份按年利率除以 12 计息。等额本息按月利率计算。 |
| 公积金利息 | 正常月供按期初本金和月利率计算。提前还款后，后续月供按新余额和剩余期数重新测算。 |
| 提前还款利息 | 预测时，分别用两类贷款本次归还的本金 × 对应年利率 ÷ 360 × 还款日的日号。例如 15 日还款按 15 天计算。这笔利息单独显示。 |
| 现金流与转息 | 首页可供提前还贷额按「本月收入 + 额外收入 − 次月月供 − 每月生活费 − 其他消费」估算，计划表逐月取当月月供。「转息差额」为该行月供合计减去转息前月供。 |

当前余额按截至今天已生效的还款计算，未来预约进入预测计划。等额本金将当期余额按剩余期数均摊。等额本息按月利率和剩余期数计算月供，再拆分本金与利息。同月多笔只扣一次正常月供本金，后续各笔根据此前累计归还的本金重新测算。普通预测的提前本金优先归还商贷，余款再归还公积金。导入的银行流水可以分别指定两类贷款实际归还的本金。

> 计划用于核对与测算，实际扣款和结清金额以贷款合同及银行账单为准。

## 数据与备份

在「还款计划 → 导入或导出」选择格式。文件写入应用文档目录的 `loan-repayment-plans/`，导出完成后界面会显示路径。同一格式下次导出会覆盖同名文件。

| 格式 | 内容和用途 |
| --- | --- |
| JSON 贷款备份 | 包含贷款参数、现金流、提前还款、历史账单、已记录的初期本金及计算出的计划行。换设备时选择「导入 JSON 备份」恢复，导入后重新计算计划。 |
| CSV / Excel 兼容文件 | 每个自然月一行，导出本息、提前本金、日期、当日利息和余额等固定字段。即使界面同月展开多笔，表格文件也按月汇总。`.xls` 内容为 Excel 可打开的 HTML 表格。 |
| 历史还款 JSON | 选择「导入历史还款 JSON」可从文件中单独读取 `paymentHistory`，按月份合并，同月以本次导入为准。 |

**贷款 JSON 备份只用于迁移贷款计划。**日历备注、扣款规则、列设置和外观偏好分别存放在本机。计算器当前算式和暂存值也只随本机贷款状态保存。导入应用导出的贷款备份会用备份中的计算器状态替换本机状态，因此原有暂存可能被清空。

<details>
<summary>历史账单 JSON 示例和字段说明</summary>

下面是一份可用「导入历史还款 JSON」读取的单月示例。金额单位为元，日期使用 `YYYY-MM-DD`。

```json
{
  "paymentHistory": [
    {
      "month": "2026-06",
      "remainingTerms": 120,
      "commercialPaymentDate": "2026-06-10",
      "commercial": { "openingBalance": 120000, "principal": 1000, "interest": 360 },
      "provident": { "openingBalance": 0, "principal": 0, "interest": 0 },
      "prepayments": [
        { "date": "2026-06-15", "commercialPrincipal": 5000, "interest": 7.50 }
      ]
    }
  ]
}
```

- `remainingTerms` 为正常扣款前剩余期数。两类贷款都填写金额组。月供实扣日可分别填写 `commercialPaymentDate`、`providentPaymentDate`。
- `prepayments` 逐笔填写日期及 `commercialPrincipal`、`providentPrincipal` 中适用的本金。提前利息未知时可省略 `interest`，界面显示「待核」。
- 商贷的 `commercialPaymentEvidence` 有三种取值。`statement` 表示账单实录，`debitMatched` 表示总扣款已核对、本息由余额反推，`estimated` 表示按历史条件重算该期月供。公积金可用 `providentInterestEstimated` 单独标记估算利息。各贷款可填写小数形式的 `annualRate`，例如 `0.036` 表示 3.6%。
- 导入会用前一期余额承接后一期，缺月按前一张账单的利率推算。新记录与后续已实扣本金冲突时，会提示冲突月份。初期本金有差异时，弹窗的「取消」保留原初期信息并继续导入，「确认」则采用从最早账单推得的日期和本金。
- 老备份中的月度合计若能由账单里同月一笔交易或全部提前还款解释，应用按实际流水核对，避免将占位记录重复扣本。

</details>

## 开发与构建

```bash
flutter analyze
flutter test
```

| 目标 | 构建命令 | 项目配置 |
| --- | --- | --- |
| Android | `flutter build apk --release` | Gradle 发布构建任务将 `pubspec.yaml` 中 `version` 的构建号加一，Debug 构建沿用原编号。当前 Release 使用调试签名。 |
| iOS | `flutter build ios --release` | 在 macOS 上构建。Runner 最低目标为 iOS 15，真机或发布签名需在 Xcode 中配置开发团队和 Bundle ID。 |
| macOS | `flutter build macos --release` | 在 macOS 上构建。 |
| Windows | `flutter build windows --release` | 在 Windows 上构建。 |

Android 构建同时生成 `build/app/outputs/flutter-apk/app-release.apk` 和同目录下的 `loan-payment-<版本名>-B<构建号>.apk`。构建号在打包过程中写回，后续步骤失败也会保留已分配的编号。
